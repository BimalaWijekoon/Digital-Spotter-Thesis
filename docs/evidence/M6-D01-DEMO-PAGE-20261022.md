# M6-D01 — Demo tab, first UI/animation slice

2026-10-22. Local UI PASS; full viva inference/hardware demo NOT complete.

## Delivered

- Demo tab beside Workout and Devices, same header, palette, feedback-first
  layout, device-status band and IMU panels. Direct link: `/ui-preview/#demo`.
- Offline 3D mannequin with barbell, separate squat/deadlift movements and
  illustrative correct/incorrect form scenarios. These are drawings, not
  measured pose, a validated biomechanics simulation or classifier decisions.
- Start, pause/resume and reset. Three six-second cycles, automatic completion;
  leaving Demo or hiding the browser pauses animation without background catch-up.
- Actual core/wearable/model status and actual live IMU vectors are shared from
  the existing UI clients through bounded/current-value browser events. No new
  BLE owner or duplicate HTTP polling client was added. If no backend exists,
  connection state remains unavailable and graphs contain no invented signals.
- Model output remains Not run. No pose estimator, replayed/generated IMU,
  classifier invocation, LED/buzzer command or saved workout is implemented by
  this slice. Load is configuration for the upcoming integration, not applied
  model inference or a quantitative plate/physics calculation.
- Pinned local Three.js r180 (MIT, original license/source/hash inventory under
  `web/static/vendor/three-r180/`). Lazy loading and client-side WebGL 2 rendering;
  no runtime CDN or external avatar dependency, no Pi rendering workload claim.
